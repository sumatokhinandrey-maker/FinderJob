# FinderJob

Телеграм-бот с ежедневным дайджестом новых вакансий для UX/UI и продуктовых
дизайнеров. Присылает только то, чего не было вчера, и только то, что подходит
под критерии конкретного человека.

Бот: [@findejobbot](https://t.me/findejobbot)

Никаких зависимостей — чистый Python, только стандартная библиотека.

## Как это работает

Две части, потому что у них разные требования ко времени.

**Разговорная часть** — вебхук на Vercel. Телеграм стучится туда при каждом
сообщении и каждом нажатии кнопки, функция отвечает за доли секунды и засыпает.

```
Telegram → api/telegram.py → профиль в Upstash Redis
```

**Ежедневный дайджест** — задача в GitHub Actions, просыпается в 07:00 МСК.
Обход hirehi занимает около трёх минут и в лимит серверless-функции не влезает,
поэтому живёт отдельно.

```
hirehi:      sitemap-vacancies-design.xml   ~1400 вакансий с датами
habr:        страницы-рубрик /vacancies/dizajner и соседние
careerspace: кураторская подборка /collection/ux_ui
hh:          публичная RSS-лента поиска, по запросу и формату работы
компании:    карьерные сайты Яндекса, VK, Т-Банка, МТС, Магнита
        │
        ▼
страница вакансии → JSON-LD JobPosting
        │            (title, компания, грейд, зарплата, город)
        ▼
склейка дублей между источниками
        │
        ▼
для каждого подписчика:
        фильтр по его критериям → отсечь показанное → отправить
```

Обход делается один раз на всех: вакансии собираются в общий список, а дальше
каждому применяются его собственные фильтры и его собственная память.

Поиск на hirehi закрыт для ботов (`robots.txt: Disallow: /*?*search=`), поэтому
ходим через sitemap — он открыт и обновляется ежедневно. Между запросами
пауза 0,5 секунды.

## Источники

**hirehi.ru** — основной поток, 15–45 дизайн-вакансий в сутки. Идём через
`sitemap-vacancies-design.xml`.

**career.habr.com** — площадка про разработку, дизайна там мало: из 1006
вакансий дизайнерских 19, поток около пяти в неделю. Берём её не ради объёма,
а ради состава: пересечение с hirehi — две компании из девятнадцати. Остальное
это Сбер, МТС Банк, Яндекс, Контур, Солар, которые на hirehi не публикуются.

Обходить весь sitemap Хабра ради двух вакансий на сотню незачем — у них есть
готовые страницы-рубрик без параметров в адресе, robots.txt их разрешает.
Известный пробел: рубрики для UX-исследователей у Хабра нет, такие вакансии
мы не увидим.

Хабр не различает гибрид: у вакансии либо стоит `jobLocationType:
TELECOMMUTE`, либо она офисная. Приписывать гибрид по наличию города —
гадание, поэтому не приписываем.

**careerspace.app** — не поток, а кураторская подборка: в `/collection/ux_ui`
ровно десять вакансий, пагинации нет. Зато компании сильные — Яндекс,
Positive Technologies, Kaspi, Uzum — и восемь из десяти не встречаются
в других источниках.

Актуальность проверена по пересечению: getmatch и Платформа ОФД есть
и у нас, их вакансии на hirehi опубликованы позавчера. Плюс номера вакансий
в подборке упираются в верх сквозной нумерации сайта.

**Зарплату оттуда не берём.** Вилка проставлена у всех десяти вакансий,
чего не бывает: у hirehi её указывает каждая четвёртая. Одна и та же вилка
«206 000 - 268 000 ₽» встречается у разных компаний и в разных профессиях —
это оценка по грейду, а не то, что написал работодатель.

Всё остальное у них за адресами с параметрами и за `/api`, а `robots.txt`
закрывает и то, и другое. Десять — это весь законный доступ.

**hh.ru** — публичная RSS-лента поиска `hh.ru/search/vacancy/rss`. Отдаётся
без токена и без логина; API для соискателей закрыт с 15 декабря 2025,
а анонимный запрос к нему возвращает 403.

Формата работы в ленте нет вовсе — как и у SuperJob, из-за чего тот источник
мы отвергли. Здесь обходим иначе: **не вытаскиваем формат из данных, а
спрашиваем отдельно удалёнку и отдельно гибрид** через `work_format`. Тогда
формат известен точно, потому что мы сами его задали.

Лента отдаёт 20 самых свежих на запрос и не листается, поэтому запросов
немного и каждый узкий. Между ними пауза 5 секунд: hh отвечает 451 на частые
обращения и отпускает через несколько секунд.

**Оговорка.** Пункт 8.8 пользовательского соглашения hh запрещает читать
информацию с сайта программными средствами, исключения для RSS там нет.
Источник подключён по осознанному решению владельца.

**Карьерные сайты компаний** — Яндекс, VK, Т-Банк, МТС, Магнит. Первоисточник:
вакансия появляется здесь раньше, чем доезжает до агрегаторов, а откликаться
можно прямо у работодателя, без регистраций и лимитов. Поэтому при склейке
дублей ссылка на карьерный сайт выигрывает у всех остальных, и в дайджесте
подписана «сайт компании».

Общего стандарта нет: у Яндекса открытый JSON с курсорной пагинацией, у VK
данные вшиты в страницу как `__NEXT_DATA__`, у Т-Банка внутренний API с POST.
Поэтому по адаптеру на компанию в `sources/companies.py`, но с общей моделью
на выходе. Упавшая компания не роняет остальные — карьерные сайты меняют
вёрстку и API без предупреждения, это их право.

Не подключены: **Точка и Альфа-Банк** — сертификат российского удостоверяющего
центра, которого нет в хранилище Python, соединение рвётся до запроса.
**Сбер, Контур, Озон, Самокат, ЦИАН** — бот-защита либо вакансии только на hh.

**Про geekjob.ru.** Подключали и убрали 26.08.2026: из 254 вакансий
дизайнерских двенадцать, живых после фильтров четыре за месяц, и все
из мелких студий. Не окупает поддержки.

**Склейка дублей.** Одна вакансия часто висит на нескольких площадках.
Отпечаток — компания, роль и город; грейд из заголовка вычищается, потому что
его пишут по-разному, а `UX/UI` и `UI/UX` сводятся к одному виду — без этого
между источниками не склеивалось вообще ничего. Город в ключе нужен, чтобы три
вакансии одного работодателя в Москве, Питере и Краснодаре не схлопнулись
в одну.

Из группы дублей берём **данные оттуда, где их больше, а ссылку — оттуда,
откуда человек сможет откликнуться**. Это разные площадки чаще, чем кажется:
hirehi подробнее всех, но прячет отклик за регистрацией и лимитом ради
подписки, а Хабр и careerspace открыты. Так в дайджест попадает полная
карточка с рабочей ссылкой.

## Что умеет бот

В меню команд нет списка slash-команд. Основное управление идёт через
закреплённую кнопку «Фильтры»: она открывает критерии и позволяет менять
каждый пункт отдельно. Для запуска настройки у нового пользователя эта же
кнопка открывает мастер.

Мастер последовательно спрашивает направление, роли, грейд, нижнюю границу
зарплаты и формат работы. Регион появляется, если подходят гибрид или офис.
При выборе ролей направление не отмечает весь каталог автоматически:
конкретные роли выбираются отдельно, а «Выбрать всё» отмечает полный список.

После настройки бот показывает сводку фильтров. Пользователь может сверить
критерии, нажать «Найти вакансии» или вернуться к их изменению. «Сбросить»
просит подтверждение и запускает настройку заново. Источники сгруппированы на
сайты компаний, агрегаторы, HH.RU, Telegram
и LinkedIn; по умолчанию включены все подключённые источники.

## Откуда берётся страна

Поле `addressCountry` в разметке hirehi бесполезно: у всех вакансий там `RU`,
включая Тбилиси, Берлин и Барселону. Поэтому Россию от заграницы отличаем
своим справочником городов — `finderjob/geo.py`.

Он же чинит написания: в данных встречается «Питер», а человек пишет
«Санкт-Петербург» — без синонимов вакансия отвалилась бы.

Справочник заведомо неполный. Незнакомый город считается неопределённым
и проходит в обе корзины — по тому же принципу, что и мягкие фильтры ниже.

## Почему фильтры мягкие

Вакансии **без указанного грейда и без вилки не отсеиваются**. Вилку на рынке
указывает примерно каждая десятая, грейд — примерно половина. Жёсткий фильтр
выкосил бы почти всё.

## Устройство

```
api/telegram.py      вебхук: команды, кнопки, мастер настройки
finderjob/store.py   профили в Upstash Redis по HTTP
finderjob/tg.py      Telegram Bot API
finderjob/wizard.py  шаги мастера, клавиатуры, тексты
finderjob/profile.py критерии пользователя и как они выглядят словами
finderjob/stats.py   счётчики событий и отчёт
core.py              фильтр, память о показанном, сборка дайджеста
sources/hirehi.py      сбор с hirehi.ru
sources/habr.py        сбор с career.habr.com
sources/careerspace.py сбор с careerspace.app
sources/hh.py          сбор с hh.ru через RSS
sources/companies.py   карьерные сайты компаний
main.py              ежедневная рассылка (запускается из Actions)
```

## Запуск локально

Положи в `.env` рядом с `main.py`:

```
TELEGRAM_TOKEN=...
KV_REST_API_URL=...
KV_REST_API_TOKEN=...
```

Дальше:

```bash
python3 main.py --dry-run              # посмотреть, ничего не отправляя
python3 main.py --dry-run --limit 20   # быстрая проверка на 20 страницах
python3 main.py --dry-run --days 7     # заглянуть на неделю назад
```

`--dry-run` не отправляет сообщения и **не трогает** память подписчиков,
поэтому гонять его можно сколько угодно.

```bash
python3 main.py --stats               # аналитика за две недели
```

## Аналитика

Своя, а не Vercel Analytics: та считает просмотры страниц через React-компонент,
а у проекта нет ни фронтенда, ни страниц — только вебхук и рассылка.

Считаем события в том же Upstash, где лежат профили: запуск бота, прохождение
мастера, открытие настроек, ввод своего города, отправку дайджеста, число
вакансий в нём и отписки. На каждое событие два счётчика — общий и дневной;
дневные живут 90 дней и исчезают сами.

Главное число — доля дошедших до конца мастера от всех запустивших бота.
Если она низкая, человек упирается в один из четырёх шагов, и видно в какой.

Сбои хранилища аналитика проглатывает молча: она не должна ронять ни вебхук,
ни рассылку.

## Раскатка

**Vercel** собирает вебхук из этого репозитория при каждом пуше в `main`.
Нужные переменные: `TELEGRAM_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и пара
`KV_REST_API_URL` / `KV_REST_API_TOKEN` от хранилища.

Вебхук регистрируется один раз:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://<домен>/api/telegram","secret_token":"<СЕКРЕТ>"}'
```

`secret_token` telegram присылает обратно в заголовке при каждом запросе —
так функция отличает настоящие апдейты от чужих.

**GitHub Actions** запускает рассылку по расписанию. В секретах репозитория
нужны `TELEGRAM_TOKEN`, `KV_REST_API_URL`, `KV_REST_API_TOKEN`.
Время меняется в `.github/workflows/daily.yml`.

## Что дальше

- **hh.ru** — вторая нога. `api.hh.ru` отдаёт 403 анонимно, нужно
  зарегистрировать приложение на [dev.hh.ru](https://dev.hh.ru) и ходить с
  OAuth-токеном. Поле `label=accredited_it` даёт фильтр по аккредитованным
  IT-компаниям
- **Дедупликация между источниками** — одна вакансия часто есть и на hh,
  и на hirehi. Понадобится вместе с hh
- **Ключевые слова от пользователя** — сейчас роль общая для всех

LinkedIn публичного API вакансий не имеет, а скрапинг запрещён их
пользовательским соглашением — по-честному этой ноги может не быть вовсе.
