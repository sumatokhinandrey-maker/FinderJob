# FinderJob

Телеграм-бот с ежедневным дайджестом новых вакансий для UX/UI и продуктовых
дизайнеров. Присылает только то, чего не было вчера, и только то, что подходит
под критерии конкретного человека.

Бот: [@findejobbot](https://t.me/findejobbot)

Никаких зависимостей — чистый Python, только стандартная библиотека.

## Как это работает

Две части, потому что у них разные требования ко времени.

**Разговорная часть** — вебхук на Vercel. Телеграм стучится туда при каждом
сообщении и каждом нажатии кнопки, функция отвечает за доли секунды и засыпает.

```
Telegram → api/telegram.py → профиль в Upstash Redis
```

**Ежедневный дайджест** — задача в GitHub Actions, просыпается в 07:00 МСК.
Обход hirehi занимает около трёх минут и в лимит серверless-функции не влезает,
поэтому живёт отдельно.

```
hirehi:  sitemap-vacancies-design.xml   ~1400 вакансий с датами обновления
habr:    страницы-рубрик /vacancies/dizajner и соседние
geekjob: страницы списка /vacancies/N — их sitemap заморожен с 2020 года
        │
        ▼
страница вакансии → JSON-LD JobPosting
        │            (title, компания, грейд, зарплата, город)
        ▼
склейка дублей между источниками
        │
        ▼
для каждого подписчика:
        фильтр по его критериям → отсечь показанное → отправить
```

Обход делается один раз на всех: вакансии собираются в общий список, а дальше
каждому применяются его собственные фильтры и его собственная память.

Поиск на hirehi закрыт для ботов (`robots.txt: Disallow: /*?*search=`), поэтому
ходим через sitemap — он открыт и обновляется ежедневно. Между запросами
пауза 0,5 секунды.

## Источники

**hirehi.ru** — основной поток, 15–45 дизайн-вакансий в сутки. Идём через
`sitemap-vacancies-design.xml`.

**career.habr.com** — площадка про разработку, дизайна там мало: из 1006
вакансий дизайнерских 19, поток около пяти в неделю. Берём её не ради объёма,
а ради состава: пересечение с hirehi — две компании из девятнадцати. Остальное
это Сбер, МТС Банк, Яндекс, Контур, Солар, которые на hirehi не публикуются.

Обходить весь sitemap Хабра ради двух вакансий на сотню незачем — у них есть
готовые страницы-рубрик без параметров в адресе, robots.txt их разрешает.
Известный пробел: рубрики для UX-исследователей у Хабра нет, такие вакансии
мы не увидим.

Хабр не различает гибрид: у вакансии либо стоит `jobLocationType:
TELECOMMUTE`, либо она офисная. Приписывать гибрид по наличию города —
гадание, поэтому не приписываем.

**geekjob.ru** — самый скромный из трёх: из 254 вакансий дизайнерских
двенадцать, и семь из них гейм-дизайн, графика и 3D, которые отсеются
стоп-словами. Остаётся около одной живой вакансии в неделю, зато пересечения
с hirehi нет вовсе.

Их sitemap мёртв — все 499 ссылок помечены 13 октября 2020 года, хотя сайт
живой. Поэтому идём по страницам списка. Поиск у них работает через `/rest/`,
куда `robots.txt` заходить запрещает, так что фильтруем у себя: заголовок,
компания и город видны прямо в списке, и страницы разработчиков мы не
открываем вовсе.

В JSON-LD у geekjob нет ни города, ни формата работы — они лежат в шапке
страницы. Грейдов у вакансии может быть несколько сразу («Миддл • Сеньор»),
поэтому в модели грейд хранится списком через запятую: отбросить второй
значит потерять вакансию.

**Склейка дублей.** Одна вакансия часто висит на нескольких площадках.
Отпечаток — компания, роль и город; грейд из заголовка вычищается, потому что
его пишут по-разному. Город в ключе нужен, чтобы три вакансии одного
работодателя в Москве, Питере и Краснодаре не схлопнулись в одну. Из дублей
остаётся запись, где больше данных — с вилкой полезнее, чем без.

## Что умеет бот

| Команда | Что делает |
|---|---|
| `/start` | короткое описание и мастер настройки на четыре вопроса |
| `/settings` | показать критерии и поменять любой пункт |
| `/stop` | отписаться, профиль стирается |

Мастер спрашивает грейд, зарплату, формат работы и город. На каждом шаге есть
«Пропустить»: оно стирает критерий и ведёт дальше — незаполненное поле
не отсекает ничего.

Зарплата и город вводятся текстом, а не выбираются из готовых вариантов.
Вилку понимаем в разных написаниях: `150000-250000`, `от 150 до 250 тысяч`,
`150к`. Города принимаем списком через запятую.

Про город спрашиваем только тех, кто выбрал гибрид или офис: человеку
на удалёнке этот вопрос ничего не даёт.

Место задаётся двумя корзинами — «города России» и «за рубежом» — плюс
своим списком городов. Корзины вместо выбора страны потому, что на нынешнем
объёме за каждой страной стоит одна-две вакансии: фильтр получился бы тоньше,
чем данные под ним.

**Что осознанно не настраивается.** Роль — продуктовый, UX/UI и веб-дизайн —
зашита в `config.json` и общая для всех. Это граница продукта: бот для
дизайнеров, а не универсальный агрегатор вакансий.

## Откуда берётся страна

Поле `addressCountry` в разметке hirehi бесполезно: у всех вакансий там `RU`,
включая Тбилиси, Берлин и Барселону. Поэтому Россию от заграницы отличаем
своим справочником городов — `finderjob/geo.py`.

Он же чинит написания: в данных встречается «Питер», а человек пишет
«Санкт-Петербург» — без синонимов вакансия отвалилась бы.

Справочник заведомо неполный. Незнакомый город считается неопределённым
и проходит в обе корзины — по тому же принципу, что и мягкие фильтры ниже.

## Почему фильтры мягкие

Вакансии **без указанного грейда и без вилки не отсеиваются**. Вилку на рынке
указывает примерно каждая десятая, грейд — примерно половина. Жёсткий фильтр
выкосил бы почти всё, а пропущенная хорошая вакансия дороже одной лишней
строчки в списке.

По той же причине в каждом дайджесте есть строка «просмотрено N, отсеяно: …».
После фильтров остаётся от нуля до восьми вакансий в день, и без этой строки
молчание бота неотличимо от поломки.

## Устройство

```
api/telegram.py      вебхук: команды, кнопки, мастер настройки
finderjob/store.py   профили в Upstash Redis по HTTP
finderjob/tg.py      Telegram Bot API
finderjob/wizard.py  шаги мастера, клавиатуры, тексты
finderjob/profile.py критерии пользователя и как они выглядят словами
core.py              фильтр, память о показанном, сборка дайджеста
sources/hirehi.py    сбор с hirehi.ru
sources/habr.py      сбор с career.habr.com
sources/geekjob.py   сбор с geekjob.ru
main.py              ежедневная рассылка (запускается из Actions)
```

## Запуск локально

Положи в `.env` рядом с `main.py`:

```
TELEGRAM_TOKEN=...
KV_REST_API_URL=...
KV_REST_API_TOKEN=...
```

Дальше:

```bash
python3 main.py --dry-run              # посмотреть, ничего не отправляя
python3 main.py --dry-run --limit 20   # быстрая проверка на 20 страницах
python3 main.py --dry-run --days 7     # заглянуть на неделю назад
```

`--dry-run` не отправляет сообщения и **не трогает** память подписчиков,
поэтому гонять его можно сколько угодно.

## Раскатка

**Vercel** собирает вебхук из этого репозитория при каждом пуше в `main`.
Нужные переменные: `TELEGRAM_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` и пара
`KV_REST_API_URL` / `KV_REST_API_TOKEN` от хранилища.

Вебхук регистрируется один раз:

```bash
curl -X POST "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://<домен>/api/telegram","secret_token":"<СЕКРЕТ>"}'
```

`secret_token` telegram присылает обратно в заголовке при каждом запросе —
так функция отличает настоящие апдейты от чужих.

**GitHub Actions** запускает рассылку по расписанию. В секретах репозитория
нужны `TELEGRAM_TOKEN`, `KV_REST_API_URL`, `KV_REST_API_TOKEN`.
Время меняется в `.github/workflows/daily.yml`.

## Что дальше

- **hh.ru** — вторая нога. `api.hh.ru` отдаёт 403 анонимно, нужно
  зарегистрировать приложение на [dev.hh.ru](https://dev.hh.ru) и ходить с
  OAuth-токеном. Поле `label=accredited_it` даёт фильтр по аккредитованным
  IT-компаниям
- **Дедупликация между источниками** — одна вакансия часто есть и на hh,
  и на hirehi. Понадобится вместе с hh
- **Ключевые слова от пользователя** — сейчас роль общая для всех

LinkedIn публичного API вакансий не имеет, а скрапинг запрещён их
пользовательским соглашением — по-честному этой ноги может не быть вовсе.
