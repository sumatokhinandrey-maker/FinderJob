# JobResearch

Ежедневный телеграм-дайджест новых вакансий для UX/UI и продуктовых дизайнеров.
Присылает только то, чего не было вчера.

Никаких зависимостей — чистый Python 3.9+.

## Как работает

```
sitemap-vacancies-design.xml   1392 вакансии, у каждой дата обновления
        │
        ├─ берём обновлённые за последние N дней
        │
        ▼
страница вакансии → JSON-LD JobPosting
        │           (title, компания, грейд, зарплата, город, опыт)
        │           формат работы — из <meta name="description">
        ▼
фильтр по профилю из config.json
        │
        ▼
seen.json — отсечь то, что уже показывали
        │
        ▼
Telegram
```

Поиск на hirehi закрыт для ботов (`robots.txt: Disallow: /*?*search=`),
поэтому ходим через sitemap — он открыт и обновляется ежедневно.
Между запросами пауза 0.5 с.

## Запуск локально

```bash
python3 main.py --dry-run              # посмотреть, ничего не отправляя
python3 main.py --dry-run --limit 20   # быстрая проверка на 20 страницах
python3 main.py --dry-run --days 7     # заглянуть на неделю назад
python3 main.py --json                 # выгрузить результат в last_run.json
```

`--dry-run` не отправляет сообщение и **не трогает** `seen.json`,
поэтому гонять его можно сколько угодно.

## Настройка фильтров

Всё живёт в `config.json`:

| Поле | Что делает |
|---|---|
| `grades` | какие грейды пропускать (`middle`). Вакансии без грейда проходят всегда |
| `include_any` | должно встретиться хотя бы одно слово, иначе отсев |
| `exclude_any` | стоп-слова: графдизайн, моушн, 3D и прочее не наше |
| `work_formats.hybrid_cities` | города, где гибрид приемлем |
| `work_formats.hybrid_abroad` | пускать ли гибрид за границей |
| `salary_min` | нижняя граница. Вакансии без указанной вилки проходят |
| `lookback_days` | за сколько дней смотреть sitemap |

Вакансии без грейда и без вилки **не отсеиваются** — на рынке вилку указывает
примерно каждая десятая, и жёсткий фильтр выкосил бы почти всё.

## Раскатка на GitHub Actions

Бесплатно и без сервера: бот просыпается раз в сутки, а `seen.json`
коммитится обратно в репозиторий.

1. **Создать бота.** Написать [@BotFather](https://t.me/BotFather) команду
   `/newbot`, получить токен вида `12345:AAH...`
2. **Узнать свой chat_id.** Написать что-нибудь своему боту, затем открыть
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти `"chat":{"id":...}`
3. **Залить репозиторий** на GitHub
4. **Добавить секреты** в Settings → Secrets and variables → Actions:
   - `TELEGRAM_TOKEN`
   - `TELEGRAM_CHAT_ID`
5. **Проверить** — вкладка Actions → «Дайджест вакансий» → Run workflow

Расписание — 07:00 МСК, меняется в `.github/workflows/daily.yml`.

## Проверить отправку локально

```bash
export TELEGRAM_TOKEN="12345:AAH..."
export TELEGRAM_CHAT_ID="123456789"
python3 main.py
```

## Что дальше

- **hh.ru** — вторая нога. `api.hh.ru` отдаёт 403 анонимно, нужно
  зарегистрировать приложение на [dev.hh.ru](https://dev.hh.ru) и ходить с
  OAuth-токеном. Поле `label=accredited_it` даёт фильтр по аккредитованным
  IT-компаниям
- **Дедупликация между источниками** — одна вакансия часто есть и на hh, и на
  hirehi. Сейчас не нужна, появится вместе с hh
- **Несколько профилей** — вынести `profile` в список, чтобы бот обслуживал
  не одного человека

LinkedIn публичного API вакансий не имеет, а скрапинг запрещён их
пользовательским соглашением — по-честному этой ноги может не быть вовсе.
